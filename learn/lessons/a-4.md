## intro
- minutes: "about 20 minutes"
- why: "Nobody can answer a permission prompt, so pass a mode every time"
- can: "write a script that runs Claude Code with no one at the keyboard"
- can: "reads its JSON result and exit code"
- can: "gets an answer in a shape you define"
- can: "limits the run to the tools and turns the job needs"
- payoff: "write a script that runs Claude Code with no one at the keyboard"
- read: "[Run Claude Code programmatically](https://code.claude.com/docs/en/headless): streaming JSON, and continuing a run with `--resume` and its `session_id`."
- need: "bash and `jq`, on macOS, Linux or WSL 2."
- need-repo: "One of your own repositories with a test command, and your copy of the practice template with Node.js LTS: the check runs from the copy."

## steps

### W1 | Worked example step 1 of 4 | Ask for two facts as JSON
- tier: challenge
- skill: ask
- where: terminal
- beat: do
- skill: headless-run
- verify: json .practice/a-4-first.json subtype=success fresh
- goal: "Ask for two facts a script can read, and save the JSON:"
- code: point 1
```bash
claude -p "What does this repository do, in one sentence, and what command runs its tests?" --output-format json --permission-mode dontAsk --json-schema '{"type":"object","properties":{"summary":{"type":"string"},"test_command":{"type":"string"}},"required":["summary","test_command"]}' > .practice/a-4-first.json
echo "exit $?"
jq '{is_error, subtype, num_turns, session_id}' .practice/a-4-first.json
jq '.structured_output' .practice/a-4-first.json
```
- hint: "Check the exit code and `is_error` before you use `result`."
- beat: do
- skill: headless-run
- verify: json .practice/a-4-first.json structured_output.test_command
- note: "then an object with a `summary` and a `test_command`, such as `"npm test"` (your values will differ)"
- say: Done when the saved JSON holds the test command in its structured output.
- hint: "A script reads one field, as `jq -r '.structured_output.test_command // empty'` does, and stops when it comes back empty."

### W2 | Worked example step 2 of 4 | Run with no one to approve
- tier: guided
- skill: mode-flag
- where: terminal
- beat: do
- verify: json .practice/a-4-denied.json permission_denials.0 fresh
- goal: "Ask for something that needs approval."
- code: point 1
```bash
claude -p "Run the test suite and say how many tests pass" --output-format json --permission-mode dontAsk --setting-sources user --disallowedTools "Read(./.env)" "Read(./.env.*)" > .practice/a-4-denied.json
jq -c '.permission_denials[] | {tool_name, command: .tool_input.command}' .practice/a-4-denied.json
jq -r .result .practice/a-4-denied.json
```
- why: "Nobody can answer a permission prompt, so pass a mode every time"
- hint: "`--setting-sources user` keeps your project's settings files out of the run"
- beat: do
- verify: self
- done-label: I read the denied call
- do: "Each line is a call that `dontAsk` denied"
- note: "Claude picks the command, so yours may differ."
- expect: "The result says Claude couldn't run the tests (your wording will differ)."

### W3 | Worked example step 3 of 4 | Allow one command, cap the turns
- tier: guided
- skill: limit-run
- where: terminal
- beat: do
- verify: self
- done-label: nothing was denied
- goal: "Allow the command step 2 listed"
- code: point 1
```bash
claude -p "Run the test suite and say how many tests pass" --output-format json --permission-mode dontAsk --setting-sources user --disallowedTools "Read(./.env)" "Read(./.env.*)" --allowedTools "Bash(npm test *)" --max-turns 3 | jq '{subtype, num_turns, denied: (.permission_denials | length)}'
```
- why: "`--allowedTools` names what may run anyway, and `--max-turns` caps the turns"
- expect: "It shows `"subtype": "success"` and `"denied": 0`: this time Claude ran the tests."

### W4 | Worked example step 4 of 4 | Stop a run at its cap
- tier: guided
- skill: limit-run
- where: terminal
- beat: predict
- ask: This task takes two steps in a row, and the cap allows one turn that calls tools. What will the saved JSON show?

- because: "`--max-turns 1` allows one turn that calls tools"
- option: A failure message in its result
- because: "such a run has no `result`"
- reveal: "a run that stops at the cap has no `result`"
- beat: do
- verify: self
- done-label: I ran it
- goal: "Hit the cap."
- code: point 1
```bash

echo "exit $?"
jq '{subtype, has_result: has("result")}' .practice/a-4-capped.json
```
- beat: do
- verify: json .practice/a-4-capped.json subtype=error_max_turns fresh
- say: Done when the saved JSON says the run stopped at the cap.
- hint: "so if the run finished, give it a task with more steps."
