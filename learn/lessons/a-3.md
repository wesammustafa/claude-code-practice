## intro
- minutes: "about 20 minutes, plus run time"
- why: "Read each script before you approve it, and stay in Manual mode for a workflow you haven't read."
- can: "have Claude write a dynamic workflow for a job that fans out across many files"
- can: "read it and keep it small before it runs"
- can: "save a migration that keeps fixing until your tests pass as a command that takes its folder from `args`"

## ladder

### a committed script in `.claude/workflows/` has a literal `export const meta`, with a `name` and a `description`, as its first statement, and reads its input from `args`
- narrow "There is no workflow script in": Did you save the run from the progress view to the project's workflows folder?
- narrow "isn't committed. Run": Does git status still list the saved script as new or changed?
- narrow "ignores it. Run `git add -f": Does an ignore rule hide the saved script from git?
- narrow "but the check reads only `.js` files directly in that folder": Is the script in a subfolder, or saved with another extension?
- narrow "doesn't start with `export const meta`": Does code come before the meta line in the committed script?
- narrow "anything but literal values": Does the meta object hold a variable, a call or a spread?
- narrow "needs a non-empty": Does the meta object lack a name or a description?
- narrow "doesn't compile": Does the committed script have a syntax error?
- narrow "never reads `args`": Does the committed script still name its folder itself?
- narrow "mentions `args` only in a comment": Is args only in a comment, a string or a property name?
- narrow "declares its own `args`": Does the script declare a variable named args?
- hint: "If the first item fails, check that the script is committed"
- bottom: "git check-ignore -v .claude/workflows/<file>.js"
- back: Y2 The script you commit is the run you saved there.

### `.practice/a-3-run1.md` and `.practice/a-3-run2.md` name two different folders on their first lines, and each cites at least one `path:line` inside its folder
- narrow "There are no reports yet": Did Claude save the first report under the practice folder?
- narrow "Run your saved workflow by name on a different folder": Is one of the two reports still missing?
- narrow "is empty. Ask Claude": Is one of the reports an empty file?
- narrow "names the repository's root": Does a report's first line name the whole repository?
- narrow "names no folder in this repository": Is a report's first line something other than a folder path?
- narrow "Both reports name": Did you run the workflow on the same folder twice?
- narrow "the folder on its first line. Check that": Does a report cite a file outside its folder?
- narrow "a path from inside": Do a report's paths start inside the folder, not at the repository's root?
- narrow "holds no such file": Does a report cite a file that isn't there now?
- narrow "cites no `path:line`": Does a report list files without a line number?
- hint: "start `claude` at the repository root so paths start there"
- hint: "ask Claude to save the report again with only the files the migration changed in that folder"

### the `git grep -E` pattern in `.practice/a-3-pattern.txt` matched inside both folders at an earlier commit, and matches inside neither at `HEAD`
- narrow "There is no `.practice/a-3-pattern.txt`": Did you save the pattern under the practice folder?
- narrow "a-3-pattern.txt` is empty": Is the pattern file empty?
- narrow "The check reads the two folders": Do both reports name their folders on their first lines?
- narrow "git can't use the pattern": Is the pattern one that git grep can read?
- narrow "is migrated in your working tree, but": Are the run's changes still uncommitted?
- narrow "still matches inside": Does the old form still show up in that folder at HEAD?
- narrow "matches nothing inside": Did the pattern ever find the old form in that folder?
- hint: "If the old form still matches at `HEAD`, commit the run's changes, or run the workflow on that folder again."
- hint: "If the pattern never matched, test it on a commit from before the run: `git grep -n -E '<pattern>' <commit> -- <folder>` should list the old form."
- bottom: "git grep -n -E '<pattern>' <commit> -- <folder>"
- back: Y1 The pattern is saved there.
