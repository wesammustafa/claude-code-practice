## ladder

### the committed `.claude/settings.json` denies reading `.env` files and allows a narrow test command
- narrow "is not committed. Run": Does git status still list the settings file as new or changed?
- narrow "There is no .claude/settings.json": Is the file saved at that path in the folder the check reads?
- narrow "is not valid JSON": Is a comma or a bracket missing, or one too many, around the rules?
- narrow "Replace each TODO": Did you commit the file again after you replaced every TODO?
- narrow "Add `Read(./.env)` to": Does one deny rule name the .env file itself, with nothing after it?
- narrow "Add `Read(./.env.*)` to": Does a second deny rule cover the files whose names start with .env and a dot?
- narrow "lets every command or every use of a tool through": Does an allow rule let in a whole program or tool, rather than the one test command?
- narrow "Add an allow rule": Is there an allow rule for the command that runs your tests?
- hint: "The committed `.claude/settings.json` denies reading `.env` and `.env.*` files and allows one test command"
- back: Y1 Review the shared rules here.

### the sandbox is on, and `.claude/settings.local.json` stays out of git
- narrow "is committed, but it holds your own settings": Did your personal settings file get committed along with the shared one?
- narrow "is not valid JSON": Did an edit by hand leave a settings file that no longer parses?
- narrow "The sandbox is off": Does your personal file override a shared enable, or is neither file enabling it?
- hint: "If the sandbox item fails, revisit Your turn step 3 in the repository the check reads; a local disable wins over a shared enable."
- back: Y3 Review the resolved sandbox setting.
