- back: Y1 Review the hook file here.
- narrow "is not committed. Run": Does git status still list the hook script as new?
- narrow "There is no .claude/hooks/protect-files.sh": Is the script saved at that path in the folder the check reads?
- narrow "isn't executable": Did the script go into the commit without its executable bit?
- hint: "Keep the protection script executable: `git ls-files -s .claude/hooks/protect-files.sh` starts with `100755`"
- hint: "run `chmod +x .claude/hooks/protect-files.sh`, then `git add` it and commit again."

### the committed `.claude/settings.json` runs it as a `PreToolUse` hook for Edit and Write
- narrow "There is no committed": Did the settings file go into a commit, at that path?
- narrow "is not valid JSON": Is a comma missing between the permissions block and the hooks block, or is there one too many?
- narrow "doesn't run protect-files.sh": Is your hooks block in the commit, or only saved in the file, and does it name protect-files.sh under the event and the matcher the lesson gives?
- hint: "`git show HEAD:.claude/settings.json | jq .hooks.PreToolUse` shows it."

### the committed hook blocks `.env` files (except `.env.example`), anything in a `secrets/` folder, `package-lock.json` and `.git/`, and allows the rest
- back: Y1 Review the match rules here.
- narrow "the check runs the committed script": Is the hook script in a commit yet, or only saved?
- narrow "couldn't run": When you run one row of the table, does the script finish at once, with a line or two of output?
- narrow "needs `jq`": Is jq installed on the machine where the check runs?
- narrow "expected 0": Does a pattern also catch a file that should pass, such as .env.example or src/config.envelope.ts, and does any path that should give 2 still give 0?
