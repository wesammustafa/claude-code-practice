## intro
- minutes: "about 20 minutes"
- why: "Commit it, and everyone who works in the repository gets it."
- can: "turn a workflow you keep repeating into a project skill, choose which requests should load it, and review the change it produces."
- payoff: "turn a workflow you keep repeating into a project skill, choose which requests should load it, and review the change it produces."
- read: "[Extend Claude with skills](https://code.claude.com/docs/en/skills): every frontmatter field, arguments, supporting files and running a skill in a subagent."
- win-note: "From this level on, the lessons are written for macOS, Linux and WSL 2."
- need-repo: "One of your own repositories with a test command and no uncommitted changes"

## warm-up

### R1 | Warm-up | Commit the shared work
- tier: challenge
- skill: commit
- from: b-5
- where: shell
- beat: ask
- ask: The team instructions changed and the local notes are personal. What should go into the shared commit?
- wrong: Both instruction files and the personal notes
- because: "Only you: add it to `.gitignore`"
- right: The project instructions and the ignore rule
- reveal: "Commit `CLAUDE.md` and `.gitignore`."

### R2 | Warm-up | Same task, long conversation
- tier: challenge
- skill: compact
- from: b-4
- where: claude
- beat: ask
- ask: The conversation is long and you are staying on the same task. What should happen to its context?
- right: Keep the relevant decisions in a summary
- wrong: Start empty for an unrelated task
- because: "The job is done and the next one is unrelated, so clear rather than compact."
- reveal: "The conversation you resumed holds the whole refactor, and you're staying on the link checker, so compact rather than clear:"

### R3 | Warm-up | An earlier conversation
- tier: challenge
- skill: resume
- from: b-4
- where: claude
- beat: ask
- ask: You want yesterday's refactor conversation, while today's latest conversation is empty. Which one should you reopen?
- wrong: The most recent conversation in this folder
- because: "`claude --continue` opens the most recent conversation in this folder instead, which after `/clear` can be the empty one."
- right: The saved refactor conversation by its name
- reveal: "open the refactor conversation again by its name"

### R4 | Warm-up | A change went wrong
- tier: challenge
- skill: rewind
- from: b-4
- where: claude
- beat: ask
- ask: An experiment changed the wrong files, and you want Claude to remember why it failed. What should recovery keep?
- right: The conversation, with the code put back
- wrong: The changed files, with the conversation summarized
- because: "The files kept, and a long stretch of conversation shrunk"
- reveal: "The files go back, and the conversation stays, so Claude still knows what it tried."

## ladder

### `.claude/skills/tdd/SKILL.md` is committed, with no TODO left
- narrow "is not committed. Run": Does `git status` list the skill as new, or does an ignore rule hide it from `git add`?
- narrow "There is no .claude/skills/tdd/SKILL.md": Is the skill saved at that path in this folder, the one the check reads?
- narrow "still has TODO": Did you save the file and commit it again after you wrote the description and the steps?
- hint: "The finished skill is committed with no TODO left: `git grep -n TODO HEAD -- .claude/skills/tdd` prints nothing."
- hint: "If the skill isn't committed, run `git check-ignore -v .claude/skills/tdd/SKILL.md`"
- hint: "an ignore rule that matches `.claude`, in a `.gitignore`, `.git/info/exclude` or your global excludes file, hides the folder from `git add`, so add the file with `git add -f`."
- bottom: "git add .claude/skills/five-whys .claude/skills/tdd"
- bottom: "git commit -m "Add project skills""
- back: Y2 Review the workflow here.

### the tdd skill can run as `/tdd` and load on its own: a description, and no `disable-model-invocation: true`
- narrow "is not committed. Run": Does `git status` list the skill as new, or does an ignore rule hide it from `git add`?
