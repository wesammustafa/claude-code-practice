## ladder

### a commit after your copy's first one changes `src/check-links.js`, which still exports a synchronous `brokenLinks`
- narrow "No commit since your copy's first": Did the synchronous refactor get its own commit?
- narrow "exports no `brokenLinks`": Does the refactor keep the function its callers import?
- narrow "is still asynchronous": Did the final refactor keep the function synchronous?
- back: W3 Revisit the decision and evidence from this step before trying the same action again.

### `.practice/b-4-before-rewind.txt` lists `src/links.js` and `src/check-links.js`
- narrow "After Claude runs the rename script": Was the before snapshot saved after both kinds of edits?
- narrow "It doesn't list": Did the script run and did Claude update its callers?
- back: Y3 Revisit the decision and evidence from this step before trying the same action again.

### `.practice/b-4-after-rewind.txt` lists `src/links.js` and no other file in `src/` or `test/`
- narrow "Right after rewinding": Did you save the state immediately after restoring code?
- narrow "still changed.": Were the remaining callers changed with a command?
- narrow "isn't changed, so": Was this file already edited by Claude in this conversation?
- back: Y3 Revisit the decision and evidence from this step before trying the same action again.

### `src/` and `test/` have no uncommitted changes, your last commit's `src/links.js` still exports `findLinks`, and `npm run linkcheck -- samples` runs without an error
- narrow "Still changed:": Which changes remain after the rewind and git recovery?
- narrow "no longer exports `findLinks`": Was the dropped rename accidentally committed?
- narrow "stops with an error.": What is the first error when the link checker runs?
- back: Y5 Revisit the decision and evidence from this step before trying the same action again.
