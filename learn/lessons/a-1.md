## intro
- minutes: "about 20 minutes"
- why: "Each session edits its own copy of the files."
- can: "run two Claude Code sessions at once, each in its own git worktree, and merge their work into one branch"
- payoff: "run two Claude Code sessions at once, each in its own git worktree, and merge their work into one branch"
- read: "[Isolate subagents with worktrees](https://code.claude.com/docs/en/worktrees#isolate-subagents-with-worktrees): `isolation: worktree` in a subagent's frontmatter gives each run a checkout of its own."
- need-repo: "One of your own repositories with a test command and no uncommitted changes, checked out on its default branch and up to date with a remote you can push to"

## ladder

### a committed `.gitignore` ignores `.claude/worktrees/` and not the rest of `.claude/`
- narrow "No committed `.gitignore` ignores": Does a committed .gitignore have a line for the worktrees folder at all?
- narrow "but that rule isn't committed": Is the rule saved in .gitignore but not committed yet?
- narrow "Only `.git/info/exclude` ignores": Is the rule only in a file git never commits?
- narrow "keeps `.claude/worktrees/` from being ignored": Does a line that starts with ! undo the rule?
- narrow "would hide the settings you share with your team": Does the rule cover more of .claude/ than the worktrees folder?
- hint: "A rule only in `.git/info/exclude` or your global excludes file isn't committed, and a broad rule such as `.claude/` would also hide the settings and skills you commit for your team."
- bottom: "git -c core.excludesFile=/dev/null check-ignore -v .claude/worktrees/x"

### `.practice/a-1-worktrees.txt` lists two worktrees under `.claude/worktrees/` whose commits split from each other, and both are merged into your branch
- narrow "While both worktree sessions exist": Did you save the listing yet?
- narrow "isn't a listing from": Did the file come from the porcelain listing, or from another command?
- narrow "Start each session with": Does the listing show both worktrees under .claude/worktrees/?
- narrow "Save the listing from this repository's main checkout": Was the listing saved in this repository?
- narrow "saved before both sessions committed": Was the listing saved before both sessions committed?
- narrow "merged into your current branch": Did you merge each branch, rather than squash or rebase it?
- hint: "save the file after both sessions commit and before you remove either worktree, and merge each branch with `git merge`."
- bottom: "git worktree list --porcelain > .practice/a-1-worktrees.txt"
- back: Y4 Save the listing while both worktrees exist and both have committed.

### neither of those worktrees still exists
- narrow "There is no": Is the listing from part 4 still there?
- narrow "lists no worktree under": Does the listing name the worktrees to remove?
- narrow "still exists and is locked": Is git holding a lock on a worktree?
- narrow "whose folder is gone": Did a worktree's folder go without git removing it?
- narrow "still exists: once its branch is merged": Is a worktree still there after its branch merged?
- hint: "If the third item fails, run `git worktree remove <path>` from your main checkout on each path the check names, with `git worktree unlock <path>` first if git says it's locked."
- bottom: "git worktree remove <path>"
- back: Y5 Merge both branches before you remove anything.
